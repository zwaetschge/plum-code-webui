# Dynamic UI v2.1 – Eigene Kacheln (model-authored tiles)

Stand 2026-11-07. Ergänzt `docs/plans/dynamic-ui-v2-2026-11-07.md`.

User request: "der agent soll wie chatgpt on the fly selber neue kacheln erstellen können anstatt auf templates zurück zu greifen".

The model may now write its own interactive tiles: self-contained HTML/CSS/JS running in a sandbox. This works like ChatGPT Apps SDK widgets with `window.openai`; ours is `window.plum`. The catalog components stay for standard cases.

## 1. Model output (done: shared + backend)

````
Text …
```plum-widget pomodoro title="Fokus-Timer" height=320
<div class="card">…</div>
<style>…</style>
<script>… plum.setState({left}) …</script>
```
```plum-ui
{"version":2,"root":{"type":"widget","id":"pomodoro","props":{…},"live":{"zrh":{"type":"weather","location":"Zürich"}}},"followups":[…]}
```
````

`extractDynamicUi` (shared) handles the blocks:
- It removes every ```` ```plum-widget ```` block from the text.
- It puts the code into `node.html` of the widget node with the same id.
- Tiles that no view references go on top: `root = stack[tiles…, root]`.
- With no view at all, it builds `stack[tiles]`.
- A patch keeps the code of a tile it places again without a new block.
- During streaming, an unfinished block sets `pending: true` and its code never reaches the text.

Clients therefore only ever see a **validated node**:

```ts
{ type: 'widget', id: string, html: string, title?: string, height?: 80..1200,
  props?: object, live?: { [name]: { type: 'weather'|'currency'|'stock'|'entity'|'news'|'gallery', …params } },
  state?: object }
```

Limits (`DYNAMIC_UI_LIMITS`):
- 4 tiles per view.
- html at most 60,000 characters.
- props and state at most 16,000 JSON characters each.
- live at most 4 entries; they count toward the 6 live widgets per view.

**Live inputs**: `collectUiLiveNodes` yields every input as a live node with the id `uiWidgetLiveId(id, name)` = `` `${id}__${name}` ``. The server therefore resolves them like normal widgets, using `turn.uiResults[`${id}__${name}`]`, the socket event `assistant:ui-result` and the refresh endpoint `…/ui/<id>__<name>/refresh`. The data shapes are those of the live widgets (snake_case, see `dynamicUiLive.ts`).

## 2. Sandbox runtime `packages/frontend/public/ui-widget.html` (done)

The same file serves both clients. Android gets an identical copy at `packages/android/app/src/main/assets/dynamic-ui/ui-widget.html`, generated by `node scripts/generate-dynamic-ui-catalog.mjs`; never edit it by hand.

- **WebUI:** load it as `<iframe sandbox="allow-scripts" src="/ui-widget.html">`.
  - Never add `allow-same-origin`, `allow-popups`, `allow-forms` or `allow-modals`.
  - The backend serves the file with a CSP header that includes `sandbox allow-scripts` (`index.ts`), `connect-src 'none'` and `img-src data: blob:`.
  - The frame has an opaque origin, so it has no cookies, no storage and no network. Verified in headless Chromium: fetch and `parent.document` are blocked.
- **Android:** `loadDataWithBaseURL("https://plum-widget.invalid/", asset, "text/html", "utf-8", null)` in a locked-down WebView (§4). The runtime detects `window.PlumAndroid.postMessage(String)`.

### Protocol (plain objects; Android passes a JSON string in both directions)

Frame → host:

| message | host does |
|---|---|
| `{plum:'ready'}` | sends `render` once |
| `{plum:'rendered'}` | hides the loading skeleton |
| `{plum:'height', value}` | inline height: `node.height` if set; otherwise clamp(value, 60, 900). Beyond 900 the frame scrolls and "Vollbild" is offered. Fullscreen fills the viewport. |
| `{plum:'state', value}` | persists the object (≤ 32 KB JSON) in the existing Dynamic UI state store under `turnId:nodeId`, the same key and persistence as checklist/quiz state |
| `{plum:'sendMessage', text}` | same as the `sendMessage` action: same busy/streaming guards, only for live (latest) turns, at most 1 per 3 s, text ≤ 2000 |
| `{plum:'prefill', text}` | same as the `prefill` action |
| `{plum:'copy', text}` | host clipboard plus the existing "Kopiert" feedback |
| `{plum:'openUrl', url}` | same as the `openUrl` action (https only, same confirmation/new-tab policy) |
| `{plum:'openEntity', title, lang?}` | same as `openEntity` (entity sheet) |
| `{plum:'refresh', name}` | refreshes live result `${id}__${name}` through the existing refresh path |
| `{plum:'display', value:'fullscreen'\|'inline'}` | enters/leaves fullscreen |
| `{plum:'image', id, url}` | loads the https URL through `/api/assistant/ui/image?url=` with the app's auth (≤ 2 MB, image/*), then replies `{plum:'image', id, dataUrl:'data:image/…;base64,…'}` or `{plum:'image', id, error}`. At most 24 per tile. |
| `{plum:'error', message}` | a subtle line under the tile ("Kachel-Fehler: …"), the first 3 only |

Host → frame:
- `{plum:'render', html, props, live, state, theme:{mode:'dark'|'light', vars:{'--plum-…': '…'}}, display}`, exactly once after `ready`.
  - `state` = the saved state, otherwise `node.state`, otherwise `{}`.
  - `live` = `{ [name]: { status:'pending'|'resolved'|'failed', data?, error?, retryable? } }` from `turn.uiResults[`${id}__${name}`]`; missing means `{status:'pending'}`.
- `{plum:'live', live}` whenever one of the tile's results changes.
- `{plum:'theme', theme}` when light/dark changes.
- `{plum:'display', value}` when the host changes fullscreen.

The host checks `event.source === iframe.contentWindow` (WebUI) and validates every field. Unknown messages are ignored.

### Theme variables

Pass resolved colour strings for:
- `--plum-text`, `--plum-muted`
- `--plum-surface`, `--plum-surface-2`, `--plum-border`
- `--plum-accent`, `--plum-accent-text`
- `--plum-good`, `--plum-bad`, `--plum-warn`
- `--plum-chart-1` … `--plum-chart-6`
- `--plum-radius`, `--plum-font`

The runtime has defaults for dark and light. Give the iframe/WebView a transparent background. **Important:** set `color-scheme` on the iframe element to the frame's mode. If the two differ, Chrome paints an opaque backdrop behind the frame.

## 4. Android host (to do)

### Validation
`DynamicUiSpec.kt` validates `widget` like the shared validator:
- html required, at most 60,000 characters.
- height 80..1200.
- props and state are objects of at most 16,000 JSON characters.
- live has at most 4 entries with NAME keys, and each is checked as a live node with id `${id}__${name}` (that id must match the ID regex).
- At most 4 widgets per view.

A broken tile becomes the usual muted fallback. Add unit tests.

### Renderer
A `WebView` inside `AndroidView`, one remembered instance per `turnId:nodeId`, destroyed on dispose.

Settings:
- `javaScriptEnabled = true`.
- Off: `domStorageEnabled`, `allowFileAccess`, `allowContentAccess`, `databaseEnabled`, geolocation and multiple windows.
- `mediaPlaybackRequiresUserGesture = true`, `cacheMode = LOAD_NO_CACHE`.
- Transparent background.

Clients:
- **`WebViewClient`:**
  - `shouldOverrideUrlLoading` returns true (no navigation).
  - `shouldInterceptRequest` answers every request with an empty 403 response, so there is no network, fonts included.
  - `onRenderProcessGone` returns true and shows the fallback; otherwise a crashing renderer kills the app.
- **`WebChromeClient`:** deny permission requests, no file chooser, console output to Log in debug builds only.

Bridge:
- `addJavascriptInterface(Bridge, "PlumAndroid")` exposing only `@JavascriptInterface fun postMessage(json: String)`.
- Hop to the main thread and validate exactly like the WebUI (§2), using the same actions as the existing Dynamic UI actions.
- Host → frame: `evaluateJavascript("window.__plumHost(" + <JSON string literal> + ")", null)`. Quote the JSON safely, as a JSON-encoded string.

Behaviour:
- **Height:** the frame reports CSS px, which equal dp at the default viewport; clamp as on the web.
- **Fullscreen:** a full-screen Dialog with its own WebView, rendered again from the saved state.
- **Images:** load through the authenticated client from `/api/assistant/ui/image?url=` and reply with a base64 data URL.
- **Live:** read `turn.uiResults["${id}__${name}"]` (already in the chat state and the socket flow).
- **Theme:** take the variables from the Compose palette.
